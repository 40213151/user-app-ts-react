
  ざっくり言うと、これは
  「重いファイル本体」と「DBに登録する処理」を分けて、サーバーに無理をさせないアップロード方式に変えた改善
  です。

  以前の問題をわかりやすく言うと、たくさんのファイルをアップロードするときに、全部をアプリケーションサーバーやGraphQLの処理にまとめ
  て渡すと、リクエストが重くなります。ファイルが多いほど、Rails側の処理時間、メモリ、DBトランザクション、タイムアウトリスクが大きく
  なります。

  そこでやったことは3つです。

  1つ目は、ファイル本体をRailsに通さず、CloudFront経由でS3に直接アップロードすることです。Railsは「このURLにアップロードしていいよ」
  という署名付きURLを発行するだけで、重いファイルデータ自体はS3側に送られます。これでRailsの負荷をかなり避けられます。

  2つ目は、アップロードを無制限に同時実行せず、3ファイルずつ並列にしたことです。全部を一気に投げるとブラウザやネットワーク、S3側にも
  負荷がかかります。一方で1件ずつだと遅い。なので「3並列」という現実的な並列数に制御して、速さと安定性のバランスを取りました。

  3つ目は、S3に上げ終わったファイルをDB登録するとき、GraphQL mutationを5件ずつに分けたことです。たとえば50ファイルを1回のmutationで
  登録すると、1つの大きな処理・大きなトランザクションになります。そこで5件ずつに分けることで、タイムアウトしにくく、途中で失敗しても
  成功分と失敗分を扱いやすくしました。
